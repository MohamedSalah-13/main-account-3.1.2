## نطاق المراجعة

الشاشة مش كلاس واحد. المراجعة غطت `AddItemController` (1013 سطر) ومعاه اللي بيكوّن الشاشة فعليًا:
`ItemForm` (سليم، متراجَع حديثًا وله `ItemFormTest`)، `BarcodeAvailability` (سليم، وله اختبار)،
`ExtraBarcodesTabController` (سليم)، `TableUnitsSetting` + `TableUnitsSettingProperty`،
و`addItem-view.fxml`، وطريق الحفظ في `ItemsService.updateItem` / `ItemsDao.insert|update`.

**الحاجات اللي اتفحصت وطلعت سليمة** (متسجّلة هنا عشان محدش يعيد فحصها):

- `AllAlerts.handleTaskFailure` بتستخدم `addEventHandler` مش `setOnFailed`، فمبتدهسش الـ handler اللي
  بيرجّع `saving` لـ false — مفيش خطر إن الأزرار تفضل مقفولة بعد فشل الحفظ.
- `ItemsDao.insertItem` بتحط الـ id المولّد على الموديل، فـ `ItemSaved` بيوصل ومعاه id صحيح.
- `ComboSetting.comboSubSetting/comboTypeSetting` بتختار بس ومبتستبدلش الـ items، فمفيش تعارض مع
  الـ `FilteredList` بتاعة `comboTypeOption()`.
- الصلاحية نفسها متحطوطة في الخدمة (`ItemsService.updateItem` بتنادي `AuthorizationGuard.require`)،
  فالشاشة مش ثغرة تفويض — الناقص هو التلميح لا الحماية (خطوة 4).
- `users` على الموديل بييجي من `DForColumnTable` = `CurrentUser.getOrNull()`، فمفيش NPE في `insertItem`.
